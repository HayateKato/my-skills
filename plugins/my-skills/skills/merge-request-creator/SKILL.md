# マージリクエスト

マージリクエスト（MR）の作成に適用する。

## 作成手順

1. 対象ブランチ、未送信コミットを確認する。
   - 未送信コミットがあればリモートに push する。
2. 以下の内容で作成する。
   - タイトルは、コミットメッセージと同じくプレフィックスと簡単な説明1文にする。Issue 番号はタイトルに書かない。
     - 例）`feat: アラートを Slack に通知する機能を追加`
   - 接続先と対象プロジェクトの確認、API の呼び出し方は CLAUDE.md の指定に従う。
   - 作成後は MR の URL をユーザーに伝える。
3. MR のパイプラインの結果を確認する。失敗していれば原因を調査して報告する。
4. マージはユーザーが行う。Claude はマージせず、レビュー待ちとして報告する。

```markdown
## 関連 Issue
関連 Issue を `Closes #<issue番号>` を含めて関連付ける。

## 変更内容
実際に実装した変更。

## テストとその結果
完了条件、完了条件が満たされていることを確認するために必要なテスト、その結果を対応づけて記述する。
ユーザーに確認してもらう項目は、未確認であることがわかるように書く。

## レビューで見てほしい点
判断に迷った点や、Issue から変えた点があれば記述する（なければ省く）。
```
