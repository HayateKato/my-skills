# ユーザー設定

## 対話・出力

- 対話は必ず日本語で行う
- 質問には短い文章で回答する
- 「鋭い指摘です」などの感想や相槌を省き、結論から簡潔に回答する
- 長文のエラーは内容をそのまま出力せず重要な部分のみ出力し、エラーの原因や対処法のみ簡潔に伝える

## Git

- コミットメッセージは、プレフィックスと簡単な説明1文だけにする。
  - 例）`update: 〇〇するために〇〇を変更`
- ブランチ名は、変更内容がわかる名前にする。
  - 例）`feat/alert-notification`

## Python

- Python のコードを書く・直すとき、または Python を実行・パッケージをインストールするときは、作業の前に必ず my-skills:python-rules スキルを読み、その内容に従う。

## Markdown

- README を含む Markdown の文章は、1文ごとに改行して書く。

## ライブラリ・ドキュメント参照

- ライブラリや外部ツールに関する情報が必要な場合は、必ず context7 MCP から最新ドキュメントを取得してから回答する

## 実装の進め方

設計判断を含むタスクは、役割を分けて進める。
mainエージェントは要件の整理・計画・指示・最終判断だけを担い、自分では実装しない。

1. 計画を立てたら、実装前に計画レビュー用のサブエージェントを起動する。
   渡すのは要件と計画だけにし、ここまでの会話は渡さない。
2. 指摘を反映したら、実装サブエージェントに計画どおり実装させ、テストも書いて実行させる。
3. 実装が終わったら、実装レビュー用のサブエージェントを新しく起動する。
   渡すのは要件・計画・diff だけにし、実装時のやりとりは渡さない。
   レビュー用サブエージェントにはテストも実行させ、実行したコマンドと結果をそのまま報告させる。
   指摘があれば、実装サブエージェントに修正させ、再び新しいレビュー用サブエージェントで確認する。
4. mainエージェントはレビュー結果や実装サブエージェントの報告を鵜呑みにしない。
   自分で diff を読み、実装レビュー用サブエージェントが実行したテストのコマンドと結果を確認して合否を決める。

レビュー用のサブエージェントは毎回新しく起動し、使い回さない。
小さな修正や設計判断を含まないタスクでは、計画レビューを省いてよい。
